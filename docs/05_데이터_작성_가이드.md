# 05. 데이터 작성 가이드: JSON / TXT / MP3

이 문서는 가장 중요합니다. 가사봄은 데이터베이스나 번역 기능을 사용하지 않으므로, **정확한 수동 입력 파일**이 곧 노래의 화면입니다.

## 2026-10-10 추가: 커버와 어려운 표현

곡별 커버는 `coverSrc: "/covers/song-id.webp"`로 연결합니다. 배경 이미지를 곡 커버로 재사용하지 않습니다. 현재 예시 3곡은 별도로 생성한 커버를 사용합니다.

곡 JSON의 선택 필드 `studyWords`에 미리 작성한 표현을 넣으면 연습실에 표시됩니다. 자동으로 번역하거나 추출하지 않습니다. 각 표현의 id는 곡 안에서 고유하며 lineId는 실제 가사 줄을 가리켜야 합니다.

```json
{
  "studyWords": [
    {
      "id": "quiet",
      "ja": "静かな",
      "reading": "しずかな",
      "koPronunciation": "시즈카나",
      "meaning": "조용한",
      "lineId": "line-01"
    }
  ]
}
```

위 항목은 전체 곡 객체에 추가하는 선택 필드입니다. `koPronunciation`은 선택이며 나머지 표현 필드는 필수입니다. 음원과 타임코드가 있는 표현은 연결 구간을 반복 재생합니다. ‘단어장에 모두 추가’와 별표는 브라우저 학습 기록에 저장합니다. 등록 자료의 표현과 사용자가 저장한 단어는 중복 표시하지 않습니다. 섹션 값은 원본 데이터에 남겨도 화면에 라벨을 표시하지 않습니다.

## 1. 파일명 및 폴더 규칙

```text
public/audio/
 ├─ song-001.mp3
 └─ song-002.mp3

content/songs/
 ├─ song-001.json
 ├─ song-002.json
 └─ _TEMPLATE.json       # 예제, 보관함에 표시하지 않음
```

- 파일명/곡 ID: `a-z` 소문자, 숫자, 하이픈 사용(예: `yoru-no-uta`).
- JSON은 UTF-8 텍스트 파일. 가능하면 편집기에서 UTF-8로 저장.
- Windows 경로 구분자 `\` 대신 JSON에는 `/` 사용.
- JSON의 `id`는 파일명과 동일해야 함. `song-001.json` ↔ `"id": "song-001"`.
- `audioSrc` 경로는 `"/audio/song-001.mp3"`. 앞에 `public`을 쓰지 않음.
- MP3가 없다면 `"audioSrc": ""`으로 저장.
- 원문/발음/해석을 파일이름이나 HTML에서 파싱하지 않고 JSON을 있는 그대로 렌더링.

## 2. 전체 JSON 예시: 타임코드 있음

```json
{
  "id": "my-song",
  "title": "노래 이름",
  "titleJa": "曲のタイトル",
  "artist": "가수 이름",
  "description": "연습할 때 참고할 메모",
  "genre": "J-POP",
  "difficulty": "보통",
  "coverTheme": "violet",
  "audioSrc": "/audio/my-song.mp3",
  "tags": ["후렴", "발음 연습"],
  "lines": [
    {
      "id": "line-01",
      "section": "1절",
      "start": 12.50,
      "end": 16.80,
      "ja": "空を見上げて",
      "koPronunciation": "소라오 미아게테",
      "koTranslation": "하늘을 올려다보며"
    },
    {
      "id": "line-02",
      "section": "1절",
      "start": 16.80,
      "end": 21.20,
      "ja": "新しい朝を待ってる",
      "koPronunciation": "아타라시이 아사오 맛테루",
      "koTranslation": "새로운 아침을 기다리고 있어"
    }
  ]
}
```

- 12.50은 **12.5초**, 16.80은 **16.8초**를 뜻함.
- 소수점은 제한 없이 사용할 수 있으나 실무적으로 소수 둘째 자리 정도면 충분.
- `start`는 줄이 시작되는 시점, `end`는 줄이 끝나는 시점.
- `start >= 0`, `end > start`, 이전 줄과 시간 겹침 없음.
- 전주가 12초면 첫 줄 `start`를 `12.5`처럼 입력할 수 있음. 전주 동안에는 첫 줄이 기본 선택되어 보이지만 재생 강조가 실제 음성 시작과 반드시 일치한다고 보장하지는 않음.

## 3. 간단 JSON 예시: 타임코드 없음

```json
{
  "id": "untimed-song",
  "title": "아직 시간을 안 맞춘 곡",
  "artist": "내가 좋아하는 가수",
  "genre": "J-POP",
  "difficulty": "쉬움",
  "coverTheme": "mint",
  "audioSrc": "",
  "tags": ["연습 전"],
  "lines": [
    {
      "id": "line-01",
      "ja": "春の風が吹いている",
      "koPronunciation": "하루노 카제가 후이테이루",
      "koTranslation": "봄바람이 불고 있어"
    }
  ]
}
```

이 경우 자동 가사 스크롤, 줄 클릭으로 재생 지점 이동, 한 줄 반복 버튼은 사용할 수 없다. 그러나 읽기/발음/해석 토글/암기/외웠다고 체크는 사용할 수 있다.

## 4. 필드 상세 사전

| 필드 | 필수 | 자료형/허용값 | 설명 |
| --- | --- | --- | --- |
| `id` | 필수 | 소문자 영문/숫자/하이픈 | URL·파일 이름·학습 기록 키 |
| `title` | 필수 | 문자열 | 홈/상세에 표시할 한글 제목 권장 |
| `titleJa` | 선택 | 문자열 | 일본어 공식 제목 등 |
| `artist` | 필수 | 문자열 | 가수/아티스트 이름 |
| `description` | 선택 | 문자열 | 연습 메모(문자 그대로 보여짐) |
| `genre` | 선택 | 문자열 | J-POP, 발라드 등 |
| `difficulty` | 필수 | `쉬움`/`보통`/`어려움` | 카드/상세 태그 |
| `coverTheme` | 필수 | `violet`/`mint`/`peach`/`blue`/`midnight` | 커버 이미지 없을 때 CSS 색 테마 |
| `coverSrc` | 선택 | `/covers/파일명` | 직접 준비한 커버 이미지 |
| `audioSrc` | 필수 | `""` 또는 `/audio/파일명.mp3` | MP3 재생 소스 |
| `tags` | 필수 | 문자열 배열 | 검색 필터에 사용 |
| `lines` | 필수 | `LyricLine[]` | 가사 줄 배열 |
| `lines[].id` | 필수 | 곡 안에서 고유 문자열 | 외운 줄 체크 저장 키 |
| `lines[].ja` | 필수 | 일본어 문자열 | 원문, 자동 변환 안 함 |
| `lines[].koPronunciation` | 필수 | 한글 문자열 | 한글 발음, 수동 입력 |
| `lines[].koTranslation` | 필수 | 한글 문자열 | 의미/해석, 수동 입력 |
| `lines[].section` | 선택 | 문자열 | 1절/후렴/브리지 등 섹션명 |
| `lines[].start` | 선택 | 초 단위 숫자 | 음원 기준 가사 줄 시작 |
| `lines[].end` | 선택 | 초 단위 숫자 | 음원 기준 가사 줄 종료 |

## 5. 타임코드 작성 전략

### 방법 A — 간단히 수동 입력

1. 평소 사용하는 MP3 재생기에서 시작/끝 시각을 확인한다.
2. 노래의 일본어 원문/발음/해석을 문장별로 나눈다.
3. 각 문장 시작/종료 시각을 JSON에 초 단위로 입력한다.
4. 사이트에서 그 줄을 눌러 실제 노래와 맞는지 듣고 수정한다.

### 방법 B — 우선 타임코드 없이 시작

1. 곡 JSON에 원문/발음/해석만 먼저 기록한다.
2. 한글 발음 보면서 곡을 외운다.
3. 반복 재생이 필요해지면 모든 줄에 시각을 입력한다.
4. `npm run validate:data`를 실행한 후 새로고침한다.

### 경계 유의사항

- 재생 속도를 변경해도 `audio.currentTime`은 원본 MP3의 시간 축을 따르므로 **타임코드 값을 배속에 맞춰 재계산할 필요가 없다**.
- 타임코드는 현재 MP3 편집본에 맞춰야 한다. 같은 곡이라도 라이브/반주/인트로 길이가 달라지면 맞지 않을 수 있다.
- 가사 없는 간주 구간은 일부러 비워 둘 수 있다. 이때 마지막 시작 가사 줄이 유지된다.
- 가사 한 줄이 너무 길면 노래의 문장/호흡 단위로 나눌 것을 권장한다.
- 모든 줄에 `start`·`end`를 기입했을 때만 자동 싱크가 활성화된다.

## 6. TXT 작성 방법

JSON 문법이 낯설면 **3줄씩 TXT**를 작성하고 제공된 변환 도구를 실행한다.

```text
@id: first-song
@title: 나의 첫 곡
@titleJa: 最初の歌
@artist: 좋아하는 가수
@genre: J-POP
@difficulty: 쉬움
@coverTheme: blue
@audioSrc: /audio/first-song.mp3
@tags: 연습, 좋아하는 가수

[1절]
[00:12.00 - 00:16.50]
空を見上げて
소라오 미아게테
하늘을 올려다보며

[00:16.50 - 00:20.00]
笑って歩いていく
와랏테 아루이테이쿠
웃으며 걸어갈 거야

[후렴]
[00:35.00 - 00:39.00]
未来へ進もう
미라이에 스스모오
미래로 나아가자
```

### TXT 문법

- `@키: 값` 형태의 헤더를 문서 맨 위에 작성. 필수는 `@id`, `@title`, `@artist`.
- 섹션: `[1절]`, `[후렴]`, `[브리지]`처럼 원하는 명칭. 다음 섹션이 나올 때까지 유지.
- 시간: `[분:초.소수 - 분:초.소수]` 형태(예: `[01:02.30 - 01:06.10]`).
- 가사: **일본어 원문 1줄 → 한글 발음 1줄 → 한국어 뜻 1줄**.
- 다음 줄 묶음 사이에 반드시 빈 줄.
- 타임코드를 안 쓰려면 **모든** 시간줄을 빼도 됨.
- TXT를 JSON으로 변환할 뿐 언어 번역·발음 생성은 하지 않음.

### 변환 실행

```bash
npm run import:txt -- content/txt/first-song.txt
npm run validate:data
```

스크립트는 `content/songs/first-song.json`을 생성한다. **같은 이름의 JSON이 이미 있으면 덮어쓰지 않고 오류를 냅니다.** 기존 JSON을 보호하기 위한 정책이다.

## 7. 검증 명령

```bash
npm run validate:data
```

검증 항목:

- JSON 파싱 가능 여부, 필수 필드와 문자열/배열 타입.
- 파일 이름과 `id` 일치 여부.
- `line.id` 중복 여부.
- MP3 경로가 로컬 `/audio/...` 형식인지.
- 설정한 MP3 파일이 실제 폴더에 있는지(없는 경우 경고).
- 모든 타임코드 값이 유효한 초 단위인지.
- 가사 시간 순서가 역전/중복되지 않는지.
- 타임코드를 일부 줄에만 작성하지 않았는지.

## 8. 일본어 한글 발음 입력 팁

이 앱은 발음을 **자동 보정하지 않고 입력 그대로 출력**한다. 일본어 장모음(おう/おお 등), 촉음(っ), 일본어 특유 리듬은 한글로 완벽히 일대일 표기되지 않는다. 내가 따라 부르기 편한 가창 중심 발음으로 일관되게 작성하되, 원음과의 차이를 듣고 수정하는 것을 권장한다.

예시:

| 일본어 | 개인 학습용 한글 발음 예 | 뜻 |
| --- | --- | --- |
| 空を見上げて | 소라오 미아게테 | 하늘을 올려다보며 |
| 君の声 | 키미노 코에 | 너의 목소리 |
| ありがとう | 아리가토오 | 고마워 |

위 표는 **읽기 편한 근사 표기**다. 원음과 완전히 같은 소리라고 보장하지 않으며, 원본 음악을 함께 들으며 개인적으로 표기 조정할 수 있다.

## 9. 저작권과 파일 보안

- 예시 노래 가사는 직접 작성된 테스트용이며 실제 발매곡을 인용한 것이 아니다.
- 상용 곡의 가사·번역·음원은 사용 권한에 맞춰 **개인 컴퓨터에서만** 보관한다.
- 배포용 저장소나 공개 게시물에 MP3·전체 가사를 올리지 않도록 주의.
- `audioSrc`는 외부 URL이 아니라 로컬 경로만 권장.
- 실제 파일 경로가 외부에 노출될 걱정은 줄였으나, PC에 악성프로그램이나 임의 사용자 접근 권한이 있는 경우까지 보호해 주는 DRM은 제공하지 않음.
