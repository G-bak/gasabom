# 24. 정적 사이트·한 곡 교체·커밋 규칙

2026-10-12 최신 사용자 결정. 23번의 하단 아이콘 재생기와 기능 축소를 유지하며, 이 문서가 설정/백엔드·Git 자료 보관에 관한 이전 설명을 대체한다.

## 정적 실행

`next.config.ts`의 `output: "export"`로 홈·보관함·현재 곡 연습실을 빌드할 때 HTML과 브라우저 JS로 생성한다. 동적 곡 경로는 `generateStaticParams`로 확정하며, 빌드 결과는 `out/`이다. 실행 시 Next.js 애플리케이션 서버, 파일 등록/백업 API, 설정 페이지가 없다. MP3·커버·폰트는 정적 파일이다.

`npm start`는 `serve`로 **out 폴더만** 127.0.0.1:3000에 제공한다. 정적 파일을 보내는 HTTP 서버이며 곡 JSON을 요청마다 읽거나 앱의 파일을 등록/수정하는 백엔드가 아니다. 다른 정적 웹 서버에도 같은 out 폴더를 사용할 수 있다. 개발용 `npm run dev`는 Next 개발 도구로 유지한다.

## 빌드와 검증

`npm run build`는 데이터 검사 → 정적 생성 → 페이지 이동용 파일 준비 → 정적 출력 검사를 수행한다. Next 16.4의 중첩 페이지 조각을 클라이언트가 요청하는 파일명으로도 저장하므로 일반 정적 호스트에서 별도 리라이트/API가 필요 없다.

`out/build-info.json`에 현재 곡 제목과 가사/음원/커버 SHA-256을 기록한다. `npm run verify:export`는 현재 자료와 출력이 같은지, 곡 페이지가 맞는지, 설정/API가 없는지 검사한다. 원본 JSON을 바꾸지 않고 빌드 결과에 실제 음원 해시로 계산한 audioRevision을 넣는다. 파일명만 같아도 음원이 바뀌면 재생 URL의 캐시 값이 바뀐다.

현재 곡과 연결되지 않은 MP3가 public/audio에 남으면 빌드/출력 검사를 중단한다. 이전 음원이 다음 곡과 함께 정적 출력/Git에 섞이지 않도록 백업 폴더로 옮긴 뒤 진행한다.

## 한 곡씩 교체

1. 이전 JSON·MP3·편집용 TXT는 별도 백업 폴더에 보관한다. 다운로드 원본을 지우지 않는다.
2. `content/songs/`에는 `_TEMPLATE.json`과 현재 곡 JSON 한 개만 둔다. 연결 MP3는 `public/audio/`, 선택 커버는 `public/covers/`에 둔다. 이전 곡 자료는 현재 자료 폴더에서 빼고 새 곡의 id·가사·시간·음원 경로를 확인한다.
3. 같은 곡을 수정할 때 기존 song.id와 line.id를 유지한다. 다른 곡이면 다른 song.id를 사용해 이전 브라우저 학습 기록과 섞이지 않게 한다.
4. `npm run build` 후 `npm start`로 확인한다. 이미 실행한 정적 미리보기는 새로고침한다. 새 곡을 넣거나 가사를 수정하면 반드시 다시 빌드한다.
5. 검사 후 Git에 커밋하고 업로드한다. 정적 호스팅에 배포할 경우 전체 out 폴더를 교체한다. Git 저장소 업로드와 사이트 호스팅 배포는 별도 작업이다.

## Git와 커밋 메시지

사용자가 승인한 **G-bak/gasabom 공개 저장소**에 코드·현재 한 곡의 MP3·JSON/TXT·웹 에셋을 함께 보관한다. 브라우저 개인 기록, 디자인 원본, 검수 백업은 제외한다. main에서 out은 생성 결과이므로 제외하며 gh-pages에는 배포용 정적 파일만 보관한다.

모든 작업 커밋 메시지에 현재 곡 제목을 포함한다. 기본 형식은 `곡 이름: 변경 내용`이며, 이번 전환은 `Pretender: 정적 사이트 전환 및 곡 자료 포함`이다.

```powershell
npm test
npm run build
npm run typecheck
git add .
npm run commit:message -- "곡 자료 교체"
npm run commit:song -- "곡 자료 교체"
git push
```

`commit:message`는 메시지만 확인한다. `commit:song`은 현재 JSON에서 곡 제목을 읽고, 활성 곡이 한 개인지와 정적 출력이 최신인지 검사한 후 **이미 스테이징한 변경만** 커밋한다. 설명을 생략하면 `곡 이름: 곡 자료 교체`를 사용한다. 업로드는 git push로 별도 실행한다.

## 유지하는 기능·기록

하단 단일 오디오, 기본 현재 곡 반복, 한 줄 반복, 줄/시간 이동, 음량, 원문·발음·뜻, 중앙 스크롤, 학습 체크·즐겨찾기·노트·단어·검색을 유지한다. 데이터는 빌드에 들어가며 개인 학습 기록은 기존 localStorage/sessionStorage를 사용한다. 서버 DB·로그인·언어 API·자동 번역/음역은 없다.

Pretender 자료는 74줄·표현 39개·318.53초이며 전사 초안 상태를 유지한다. 공식 대조와 전체 청음 검수 완료로 표시하지 않는다.

## GitHub Pages 공개 배포 (최신 결정)

2026-10-12 사용자가 GitHub Pro의 월 4달러 요금과 사이트 공개 범위를 확인한 뒤 “그럼 그냥 공개로 바꿔”라고 요청했다. 저장소를 공개로 전환하고 무료 Pages로 사이트를 게시한다. 아래의 이전 개인 접근 결정은 이 지시로 대체됐다. 저장소 이력·MP3·가사와 사이트가 공개되며, 개인 학습 기록은 각 브라우저에만 저장된다.

배포 주소는 **https://g-bak.github.io/gasabom/**이며 Pages 설정은 **Deploy from a branch / gh-pages / /(root)**이다. Next의 basePath를 `/gasabom`으로 빌드하고 일반 이미지·음원·아이콘에도 같은 경로를 적용한다. Next Link/router 경로는 자동 적용한다. 로컬 빌드에서는 기본 빈 경로를 유지한다.

곡 교체 검사와 곡 이름 커밋을 main에 push한 뒤 `npm run deploy:pages`를 실행한다. 작업 폴더가 깨끗하고 원격 main과 같은 커밋인지 확인한 다음 Pages용 정적 출력/타입을 검사해 gh-pages 브랜치에 전체 출력과 `.nojekyll`을 올린다. 기존 배포 파일을 교체하므로 이전 곡 파일이 현재 배포에 남지 않는다. 배포 커밋 메시지에도 현재 곡 제목과 원본 main 커밋이 들어간다. 완료 후에는 로컬 미리보기용 기본 경로로 다시 빌드한다.

main push와 사이트 배포는 별도이므로 Actions/Pages에서 실제 게시와 사이트 접속을 확인한다. 구매·유료 요금제 변경은 하지 않는다. 검색 제외는 유지하지만 접근 제한이 아니다.

### 이전 확인 이력

2026-10-12 사용자가 GitHub Pages 배포를 요청한 뒤, 공개 범위를 확인하고 **“나만 접속해야 함”**을 선택했다. 당시 G-bak/gasabom은 개인 계정 소유의 비공개 저장소였으며 Pages 설정은 “Upgrade or make this repository public to enable Pages”로 표시됐다. Pages API 조회도 설정된 사이트가 없는 404였다.

비공개 저장소에서 Pages를 사용할 수 있는 요금제로 올려도 개인 계정의 사이트는 공개된다. 사이트를 비공개로 게시하는 기능은 Enterprise Cloud 조직 소유의 비공개/내부 저장소에 적용된다. 당시 개인 접근 조건에서는 Pages 배포를 진행하지 않았다. 이후 공개 전환 요청으로 결정이 바뀌었으며 유료 요금제 변경은 하지 않는다.

현재 사용 주소는 로컬 `http://127.0.0.1:3000`이다. 원격 접속을 도입하려면 정적 페이지와 MP3·가사 파일 모두에 로그인 등 접근 제한을 적용하는 호스팅을 선택해야 한다. `robots: noindex`와 주소를 숨기는 방식은 개인 접근 보장이 아니다.
