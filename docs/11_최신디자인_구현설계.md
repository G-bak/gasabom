# 11. 최신 디자인 구현 설계와 준비 검토

2026-10-09 · 설계 확정 및 구현 준비 기록. 2026-10-10 구현 진행 상태 추가. 이 문서는 초기 제공본의 00~09 문서와 충돌하는 부분을 대체한다. 전체 구현 완료 보고서가 아니다.

앱은 개인용 localhost 서비스다. React·Next.js App Router·TypeScript, 로컬 MP3와 JSON/TXT, 브라우저 학습 기록을 유지한다. DB·회원가입·결제·클라우드·자동 번역·자동 음역·외부 가사 및 음원 수집을 추가하지 않는다.

## 2. 화면과 경로

2026-10-10 추가 지시에 따라 웹 가이드 페이지와 메뉴를 제거했다. 화면 내 파일 확인/설정 링크는 /settings로 연결한다. PC 컨테이너는 calc(100% - 240px)이며 좁은 화면은 기존 반응형 여백을 사용한다.

| 화면 | 경로 | 기능 |
| --- | --- | --- |
| 홈 | `/` | 새 시안의 상단 메뉴·히어로·사용 흐름·학습 기능·개인 보관함 곡 미리보기·시작/데모 버튼 |
| 보관함 | `/library` | 검색, 장르 필터, 즐겨찾기, 최근 연습, 암기 완료, 정렬, 카드/목록 보기, 플레이리스트, 실제 기록 통계·아티스트 요약 |
| 연습실 | `/songs/[slug]` | 일본어·발음·뜻 3열, 현재 줄 동기화, 배속, 줄 반복/A–B, 암기, 집중 보기, 북마크, 노트, 수동 단어장 |

설정은 탭으로 구성한다. 파일 등록, 목록, 미리보기, 형식 설명, 검증 결과를 실제 데이터로 연결한다. 상단 아바타는 개인 설정으로 연결하며 온라인 계정 기능으로 확장하지 않는다. 소셜 링크는 개인 설정에 실제 URL을 입력한 경우만 연결하며 임의 계정·가짜 연락처를 만들지 않는다. 이용 안내는 가이드로, 데이터 보관 안내는 로컬 저장·백업 설명으로 연결한다.

보관함으로 이동해도 같은 곡의 재생은 이어진다. 등록곡이 없으면 등록 안내를, 검색 결과가 없으면 조건 초기화와 빈 결과 안내를 제공한다. 시안의 곡/가수/앨범 이미지는 자리표시 자료이며 구현 데모는 기존 자체 작성 곡을 사용한다.

- 라이트·다크 로고, 텍스트 없는 심벌, 파비콘, 앱 아이콘은 `design/브랜드에셋_목록.json`의 현재 에셋을 사용한다.

## 4. 로컬 등록·관리와 데이터 계약

### 저장 위치

곡 원본은 `content/songs/<song-id>.json`, 음원은 `public/audio/<song-id>.mp3`, 선택 커버는 `public/covers/`에 저장한다. 등록 UI의 파일 선택은 외부 서버 업로드가 아니라 실행 중인 localhost의 Node.js 파일 처리다. 사용자가 선택한 파일을 프로젝트 안으로 복사하고 기존 외부 원본은 지우지 않는다.

노트·단어장·플레이리스트·즐겨찾기·학습 체크·보기 옵션·최근 재생은 브라우저의 버전 있는 저장 구조에 저장한다. 음원 전체를 localStorage에 넣지 않는다. 서버 파일 쓰기는 승인된 데이터 폴더에 한정하고 원본 ZIP, design, 소스 코드, 임의 경로를 수정하지 않는다.

### 파일 등록

- MP3, JSON, TXT의 선택·드래그 등록과 제목/가수/설명/태그/난이도 편집을 제공한다. JSON/TXT를 먼저 등록해도 수동 연습이 가능하다.
- 초기 파일 제한은 시안 기준 MP3 100MB, JSON/TXT 10MB다. 허용 형식·누락·타임코드 오류·용량 초과를 항목별로 보여준다.
- JSON/TXT와 MP3를 곡 단위로 연결하고 저장 전 곡 제목·가사·재생 미리보기 및 변경 경로를 표시한다. 경로만 없는 MP3를 자동으로 다른 곡과 연결하지 않는다.
- 원본 파일명은 한글·일본어여도 선택 가능하게 한다. 저장 파일명은 안정적인 song.id로 정하고 audioSrc는 `/audio/<song-id>.mp3`로 연결한다.
- 최초 id가 없는 입력은 등록 화면에서 id를 생성·확정한다. 이미 등록한 곡은 제목·가사 수정으로 song.id/line.id를 불필요하게 바꾸지 않는다.
- 정식 가사 필드는 `ja`, `koPronunciation`, `koTranslation`, `start`, `end`다. 시안의 `koPron`/`koMeaning`은 가져오기에서 정식 필드로 대응한다. 두 표현이 함께 있고 값이 다르면 충돌을 보여주며 임의로 한쪽을 버리지 않는다. 의미/발음 텍스트 자체를 생성·번역하지 않는다.
- 시간 정보는 모든 줄에 있거나 모두 없어야 한다. 등록·편집·TXT 변환과 기존 CLI 검증에서 같은 검증 규칙을 사용한다.
- 동일 id/파일명이 있으면 새 곡 등록을 막고 기존 곡 편집 흐름으로 안내한다. 덮어쓰기·삭제는 대상과 영향을 확인한 후 실행한다.
- 저장은 검증 완료 후 임시 파일과 안전한 교체 절차를 사용한다. 실패하면 부분 등록·손상된 JSON·반쪽짜리 곡이 남지 않게 한다.
- 파일 변경 API는 loopback 실행 및 같은 출처 요청을 전제로 한다. 파일명과 경로는 서버에서 검증하며 브라우저가 임의 PC 경로를 지정하게 하지 않는다.

곡 삭제 시 연결된 플레이리스트·기록에 미치는 영향을 표시한다. 다른 곡이 공유하는 파일은 삭제하지 않는다. 재생 중인 곡을 삭제하면 재생을 중단하고 보관함으로 안내한다.

## 5. 공통 플레이어·연습실

앱 전체에 실제 audio 인스턴스는 하나만 둔다. 연습실 상단과 하단, 홈/보관함 재생 버튼은 같은 상태를 제어한다. 같은 곡으로 페이지를 이동하면 시간·배속·음량이 이어지고, 다른 곡 선택 시 이전 A–B와 임시 암기 공개 상태를 초기화한다.

현재 곡, 재생 시간, 전체 길이, 속도, 음량, 오류, 반복 구간을 공통 상태로 관리한다. 기본 자동 재생은 하지 않는다. 파일이 없거나 재생 오류가 있으면 안내와 재시도/자료 관리 연결을 제공한다.

3열 가사는 세 개의 독립 목록으로 구현하지 않는다. 같은 line.id를 가진 한 행의 일본어·발음·뜻을 정렬하고 선택·스크롤·반복 상태를 공유한다. 긴 번역에서도 각 언어의 줄 대응이 틀어지지 않아야 한다.

- 줄 선택: 해당 시간으로 이동 또는 수동 선택.
- 암기 정답 확인: 재생 위치를 바꾸지 않고 가려진 내용을 보여줌.
- 외운 줄 체크: 학습 기록만 변경.
- 북마크: 나중에 돌아갈 곡/줄 표시. 즐겨찾기와 구분.
- 줄 반복과 직접 지정 A–B: 같은 반복 상태를 사용. 잘못된 경계와 음원 길이 초과를 안내.
- 셔플/이전·다음 곡: 현재 선택한 플레이리스트 또는 보관함의 재생 가능 곡을 기준으로 동작. 가사 줄 전후 이동과 별도 컨트롤로 구분.
- 암기/집중/재생속도/언어 표시/자동 스크롤/단축키는 기존 기능을 유지한다. 작은 화면에서도 접근 가능하게 한다.

타임코드 자동 생성은 하지 않는다. 수동으로 시작/끝을 기록하고 수정할 수 있는 편집 기능을 자료 관리에 포함한다. 부분 입력은 임시 편집 상태로 보관하고, 미완성 시간 정보를 정식 곡 JSON에 저장하지 않는다. 그동안 기존의 시간 없는 JSON으로 수동 연습한다. 모든 줄의 작성 완료 후 전체 검증을 거쳐 시간을 정식 데이터에 반영하고 동기화를 켠다.

## 6. 노트·단어장·플레이리스트

### 노트

곡별 노트를 작성·수정·삭제하고, 선택적으로 line.id에 연결한다. 노트는 최대 500자이며 빈 글 저장을 막는다. 사용자 노트 목록·곡별 필터와 저장 상태를 제공하고 새로고침 후 유지한다.

### 수동 단어장

`id`, 일본어 단어, 사용자가 입력한 읽는 법, 한국어 뜻, 별표, 연결 song.id/line.id를 저장한다. 추가·편집·삭제·검색·즐겨찾기와 곡별 단어 목록을 제공한다. 읽는 법·뜻을 자동 추론하지 않는다.

단어 재생 버튼은 연결된 로컬 음원의 시간 구간이 있을 때 그 구간을 재생한다. 구간이 없는 단어는 텍스트 학습이 가능하고 발음 버튼은 사용 불가 이유를 표시한다. 외부 음성 API에 단어를 보내지 않는다.

### 로컬 플레이리스트

`id`, 이름, 정렬된 song.id 목록을 저장한다. 만들기·이름 변경·삭제·곡 추가/제거·곡 순서 변경·연속 재생·셔플을 제공한다. 동일 곡을 중복 추가하지 않는다. 등록된 곡이 삭제되면 빠진 곡을 표시하거나 참조를 정리하며 목록을 깨뜨리지 않는다.

시안의 ‘최근 연습’, ‘암기 완료’는 실제 상태에서 계산한다. ‘전체 곡’·장르·즐겨찾기·카드/목록·최신 추가순·제목/가수 정렬은 실제 필터/설정으로 동작한다.

## 7. 기록·설정·통계

학습 저장 구조는 버전을 가진다. 기존 `gasabom:practice:v1`의 favorites/learned/options를 유지하며 새 구조로 이관한다. 이전 기록은 성공 확인 전 지우지 않는다. 화면마다 별도 상태가 엇갈리지 않도록 공통 저장 상태를 사용한다.

새 기록은 노트, 단어장, 플레이리스트, 북마크, 최근 재생 시각, 실제 청취 누적 시간, 개인 설정을 포함한다. 제목 변경은 id 기반 기록을 보존한다. 삭제된 줄·곡의 id는 진행률 분모/분자 계산에서 제외하고 노트·단어 연결은 적절히 표시한다.

통계는 전체 곡 수·즐겨찾기·유효 체크 줄·암기 완료 곡·실제 재생 시간·아티스트별 곡 수로 계산한다. 일시정지·시크·단순 페이지 열기를 청취 시간으로 누적하지 않는다. 시안의 129곡·48시간 등의 예시 숫자는 넣지 않는다.

설정에는 표시 언어, 글자 크기, 자동 스크롤, 기본 속도/음량, 카드/목록 보기, 개인 표시 정보를 제공한다. 저장이 차단되면 현재 세션은 사용 가능하게 하고 저장이 되지 않았음을 표시한다.

## 8. 백업·복원

학습 기록 백업은 버전 있는 JSON이다. 즐겨찾기·외운 줄·노트·단어·플레이리스트·북마크·보기 옵션·최근 기록을 포함한다. MP3는 이 JSON에 포함하지 않는다는 점을 화면에 설명한다.

곡 자료 백업은 JSON·MP3·선택 커버와 자료 목록을 담은 ZIP으로 다운로드한다. 앱 코드·node_modules·design·인증 정보·임의 PC 파일은 백업 대상에 넣지 않는다.

복원은 파일 형식·버전·곡/줄 참조·충돌을 먼저 검사하고 추가/교체될 항목을 보여준다. 사용자가 선택한 병합 또는 교체 정책을 적용하며 기존 자료를 묵시적으로 덮어쓰지 않는다. 실패한 복원은 기존 자료를 보존한다. 알 수 없는 버전과 범위 밖 파일 경로는 오류로 안내한다.

브라우저·호스트·포트가 바뀌면 학습 기록이 달라 보일 수 있으므로 접속 주소를 고정하고 백업/복원으로 이동할 수 있게 한다.

## 10. 구현 순서와 완료 조건

구현은 시작 가능하다. 전체 기능은 이번 범위에 포함하되 아래 순서로 완성한다.

1. 설치·기존 타입/빌드 확인 → 현재 예제의 실패 지점 수정 → lock 파일 확보.
2. 새 공통 레이아웃·브랜드·홈·보관함·연습실·가이드·설정 구조와 웹용 자산.
3. 공통 저장 상태·단일 오디오·3열 가사·기존 학습 기능 보존.
4. 로컬 파일 등록·검증·수동 시간 편집·자료 관리.
5. 노트·단어장·북마크·플레이리스트·실제 통계·개인 설정.
6. 학습 기록 및 곡 자료 백업/복원 → 전체 실제 브라우저 검수.

완료 검수는 기존 T01~T28에 다음 항목을 추가한다: 새 곡 등록 후 서버 재시작 반영, 중복/잘못된 자료/부분 타임코드 오류, 자료 수정 시 학습 id 유지, 재생 중 페이지 이동, 긴 3열 가사의 줄 대응, 노트/단어/플레이리스트 새로고침 보존, 단어 구간 재생과 데이터 없음 상태, 연속/셔플 재생, 청취 통계의 시크/일시정지 제외, 백업 복원 왕복 및 충돌 처리, 저장 차단, 1440/1024/768/390px UI와 키보드 조작.

설계 검토 당시에는 Node 22.14.0/npm 10.9.2와 데모 3곡 데이터 검증만 확인했다. 이후 1단계 설치·기본 실행 검증([12번 결과](12_기존코드_실행검증_결과.md))과 2단계 새 디자인 적용·브라우저 검수([14번 결과](14_새디자인_적용_결과.md))를 완료했다.

2026-10-12 현재는 네 화면과 공통 오디오, 실제 파일 등록·편집·삭제, 수동 시간 편집, 노트/단어/플레이리스트 관리, 학습 기록 복원과 곡 자료 ZIP 백업·복원을 구현했다. 상세 동작과 한계·최종 검증은 [22번 운영 기록](22_현재상태_운영과검증.md)을 따른다. Pretender 가사 자료의 공식 대조·전체 청음 검수는 계속 남아 있다.
