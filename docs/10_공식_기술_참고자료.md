# 10. 공식 기술 참고자료와 설계 근거

> 정리 기준: **2026-10-09**. 공식 문서 페이지는 향후 개정될 수 있으므로, 패키지 설치 시 현재 사용하는 Next.js 버전과 비교한다.

## 1. Next.js — App Router

- [Next.js 공식 문서: App Router](https://nextjs.org/docs/app)
  - 경로 기반 라우팅과 서버·클라이언트 컴포넌트 분리를 설계하는 근거.
  - 이 프로젝트: `app/page.tsx`, `app/songs/[slug]/page.tsx`, `app/guide/page.tsx`.
- [Next.js 공식 문서: public Folder](https://nextjs.org/docs/app/api-reference/file-conventions/public-folder)
  - `public` 안에 넣은 정적 파일을 `/` 기준 경로로 참조하는 규칙.
  - 예: `public/audio/song.mp3` → 브라우저 URL `/audio/song.mp3`.
  - **주의:** 프로덕션 빌드와 런타임 정적 파일 추가 방식은 버전/배포 방식에 따라 확인해야 한다. 개인 로컬 개발 환경에서는 `npm run dev` 사용을 권장.

## 2. MDN — 미디어 재생속도

- [HTMLMediaElement.playbackRate](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/playbackRate)
  - 오디오 요소의 재생 속도 배율 설정. `1.0` 기본, 1보다 작으면 느린 재생.
  - 가사봄의 0.75x/0.85x/1.0x/1.15x/1.25x 옵션 근거.
- [HTMLMediaElement.preservesPitch](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/preservesPitch)
  - 속도 변경 시 피치를 가능한 한 보정하도록 요청하는 속성.
  - 브라우저·코덱/재생 환경에서 품질 차이는 발생할 수 있음.
- [Web audio playbackRate explained](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Audio_and_video_delivery/WebAudio_playbackRate_explained)
  - HTML 오디오 재생속도 관련 기본 구현 예시.

## 5. 구현 시 웹 기술 주의사항

- 자동 재생 정책 때문에 로딩 시 무음 없이 바로 자동 재생하려고 하지 않는다. 사용자가 재생을 누르게 한다.
- 시각 표시용 글자 읽기와 음악 시간의 연결은 **사전에 작성된 타임코드**에 의존한다. 음성인식·가사 자동 싱크는 제공하지 않는다.
- HTTPS 웹 배포가 아니라 localhost 웹앱이므로 서비스용 HTTPS/도메인/호스팅 과제를 추가할 필요가 없다.
- 로컬 접속만 한다고 해서 의존성 설치나 개발 도구까지 인터넷을 절대 사용하지 않는다는 의미는 아니다.
