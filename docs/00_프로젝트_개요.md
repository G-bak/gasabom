# 00. 가사봄 프로젝트 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트명 | **가사봄 (GASABOM)** |
| 한 줄 소개 | **읽을 수 없어도, 따라 부를 수 있게.** |
| 제품 형태 | 1인 개인용 로컬 J-POP 가사 연습 웹사이트 |
| 핵심 사용자 | 일본어를 읽기 어렵지만 일본 노래를 따라 부르고 싶은 한국어 사용자 |
| 프론트엔드 | React + Next.js App Router + TypeScript |
| 데이터 저장 | 프로젝트 폴더의 JSON / 선택적으로 TXT→JSON 변환 |
| 음악 파일 | 직접 준비한 MP3, 로컬 `public/audio/` |
| 앱 저장 기능 | 브라우저 localStorage (즐겨찾기, 외운 줄 체크, 보기 옵션) |
| 별도 DB | **사용 안 함** |
| 번역/음역 자동화 | **구현 안 함** — 사람이 작성한 결과를 화면에 표시만 함 |
| 배포 | **필요 없음** — `127.0.0.1:3000`에서 실행 |

## 1. 네이밍과 정체성

**가사봄**은 '가사를 보다'와 봄의 가볍고 따뜻한 인상을 합친 이름이다. 한글로 읽기 쉽고, 음악 학습의 부담을 덜어 주는 개인 음악 다이어리의 이미지를 표현한다.

- 브랜드명: **가사봄**
- 영문 표기: **GASABOM**
- 태그라인: **읽을 수 없어도, 따라 부를 수 있게.**
- 메인 카피: **좋아하는 노래를 나의 언어로 부르는 시간.**
- 주된 정서: 따뜻함 / 차분함 / 내 공간 / 한 줄씩 성장

## 2. 해결할 문제

실제 어려움은 일본어를 몰라 '번역할 방법이 없어서'가 아니라, 이미 갖고 있는 곡/원문/한글 발음/번역을 **음원과 자연스럽게 연결한 연습 화면이 없어서**이다.

1. 일본어 가사를 읽기 어렵다.
2. 한글 발음만 따로 보면 노래의 어느 부분인지 찾기 어렵다.
3. 가사·발음·뜻을 번갈아 보느라 따라 부르기에 집중하기 어렵다.
4. 어려운 한 소절을 반복 재생하려면 플레이어에서 계속 되감아야 한다.
5. 암기 여부가 기억에만 남고 표시되지 않는다.

## 3. 사용자에게 약속할 결과

- **한 화면 안에서** 일본어 원문·한글 발음·한국어 뜻을 확인한다.
- 노래 재생 시 **현재 문장**을 찾기 쉽다(타임코드 입력 시 자동 강조).
- 한 줄 또는 원하는 구간을 **원하는 만큼 반복**한다.
- 발음·뜻을 가리는 **암기 연습**을 한다.
- 외웠다고 생각한 문장을 **체크**해서 기록한다.
- 외부 서비스에 개인 음원이나 가사를 보내지 않는다.

## 4. 제품 성공 기준 (개인 사용 관점)

- 첫 실행에서 데모 목록과 가사 UI가 보인다.
- 문서만 참고해 첫 개인곡 JSON/MP3를 추가할 수 있다.
- 타임코드 없는 곡도 오류 없이 가사 읽기가 가능하다.
- 타임코드가 있는 곡은 1줄 반복과 자동 강조가 작동한다.
- 브라우저를 새로고침해도 즐겨찾기와 외운 줄 체크가 남는다.
- 외부 API 자격증명이나 별도 데이터베이스 설치가 불필요하다.

## 5. 범위 정의

### 이번 제공 범위

**동작하는 로컬 웹 예제 + 기획/설계 문서 + 데이터 템플릿 + 샘플 음원 + TXT 변환·검증 도구**. 사용자는 코드를 처음부터 작성하지 않고도 `npm install → npm run dev`로 시작할 수 있는 구조를 받는다.

### 명시적으로 제외

| 제외 | 이유 |
| --- | --- |
| 온라인 J-POP 가사 검색·스크래핑 | 사용자가 가사를 제공함 |
| 일본어 자동 번역 | 사용자가 번역을 제공함 |
| 일본어→한글 발음 자동 변환 | 사용자가 발음을 제공함 |
| Spotify / YouTube 등 스트리밍 연동 | MP3를 로컬에서 직접 사용함 |
| 회원가입·로그인·계정 동기화 | 1인 로컬 사용 |
| 데이터베이스/서버 업로드 | 작은 정적 JSON으로 충분함 |
| 라이브러리 곡 웹 업로드 관리자 | 파일 편집기로 관리하는 것을 전제로 함 |
| 노래 발음 AI 채점 | 요구 범위 외이며 별도 처리 필요 |
| 상용 서비스/결제/광고 | 개인 취미용 |

## 6. 기본 이용 시나리오

1. 개인 보유 MP3를 `public/audio/`에 복사한다.
2. 준비한 가사·발음·번역을 `content/songs/song-id.json`에 기록한다.
3. 필요한 경우 문장 시작/종료 시각을 초 단위로 작성한다.
4. `npm run validate:data`로 형식 오류를 검사한다.
5. `npm run dev`로 실행하고 곡을 선택한다.
6. 한글 발음을 보면서 듣는다 → 재생 속도를 낮춘다 → 반복한다 → 암기 도전 → 외운 줄 체크.

## 7. 먼저 알아둘 트레이드오프

- 타임코드 없는 데이터는 **자동 싱크 불가**. 대신 수동 가사 보기 제공.
- MP3 없는 곡은 **재생 불가**. 대신 가사 읽기/학습 체크 제공.
- 브라우저 저장 데이터는 다른 브라우저로 자동 동기화되지 않고, **사이트 데이터 삭제 시 사라질 수 있음**.
- Next.js는 React 앱과 로컬 파일을 제공하는 서버를 구동하므로 **Node.js 프로세스가 실행 중**이어야 한다. 단, 원격 서버를 사거나 24시간 켜둘 필요는 없다.
- 느린 재생의 음질과 피치 보존은 브라우저의 미디어 구현에 영향을 받는다.
