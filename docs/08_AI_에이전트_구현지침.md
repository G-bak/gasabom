# 08. AI 개발 에이전트용 구현·개선 지침

> **최신 범위 변경:** 2026-10-09 사용자가 디자인 시안의 전체 기능과 로컬 파일 등록·관리를 승인했습니다. [11_최신디자인_구현설계.md](11_최신디자인_구현설계.md)와 루트 AGENTS.md가 아래 초기 예제 지침보다 우선합니다. 아래의 업로드 UI·노트·단어장·플레이리스트 제외 규칙은 현재 범위에 적용하지 않습니다. DB·계정·클라우드·자동 언어 처리 제외는 유지합니다.

> 이 문서는 가사봄 프로젝트를 다른 코드 에이전트에 전달할 때 그대로 읽히도록 작성한다. **이미 웹 소스가 구현되어 있으므로, 요구사항 재해석보다 현재 구현을 점검·수정하는 것이 첫 업무**다.

## 0. 최상위 규칙 (위반 금지)

**사용자는 일본어를 읽지 못하지만 J-POP을 좋아하는 한국어 사용자다. 사용자가 미리 갖고 있는 일본어 가사, 한글 발음, 한국어 뜻, MP3를 한 화면에 출력하고 싶어 한다.**

이 프로젝트를 상용화용 SaaS나 AI 번역 서비스로 확대하면 요구사항을 위반한다.

반드시 지킬 것:

1. 프론트 React + Next.js App Router + TypeScript.
2. 로컬 개발 서버; 기본 `127.0.0.1:3000`.
3. 별도 DB 금지, JSON/선택적 TXT만 사용.
4. 음원은 사용자가 제공한 로컬 MP3만 사용.
5. 번역 API, 발음 변환 API, 웹 가사 검색/스크래핑, AI 언어 처리 **절대 추가하지 않음**.
6. 회원가입, 업로드 서버, 결제, 공유, 광고, SNS 기능 **추가하지 않음**.
7. 고정된 개발 스택으로 UI를 구현하며, 과도한 새 종속성을 추가하지 않음.
8. 독창적 예시 가사 및 자체 데모 MP3만 포함; 상용 곡 파일은 사용자 몫.

## 3. 유저 중심 개발 기준

- 노래 제목보다 **한글 발음**이 중요하다. 시선을 현재 줄 + 발음으로 유도한다.
- 한글 발음이 길어질 수 있으므로 줄바꿈/가변 폭을 허용한다.
- 일본어 표기가 한자로 길더라도 글자 폭이 깨지지 않도록 한다.
- 타임코드가 없다는 이유로 곡을 숨기지 않는다.
- MP3가 없다는 이유로 읽기/암기 기능을 막지 않는다.
- 연습 기록은 곡 이름이 아니라 영속적 식별자(`song.id`, `line.id`)에 매핑한다.
- 홈에 들어올 때마다 불필요한 외부 데이터 조회를 하지 않는다.
- 애니메이션은 음악/가사 읽기를 방해하지 않아야 한다.

## 4. 코드 변경 전 검사할 불변 조건

```text
A. JSON 경로를 브라우저가 직접 읽지 않는다. 서버 fs 접근만 사용한다.
B. localStorage는 서버 렌더 단계에서 읽지 않는다.
C. isFullyTimed(song) = 모든 가사 줄에 start/end가 유효할 때만 true.
D. audioSrc == ""이면 모든 음원 컨트롤이 안전하게 비활성이다.
E. JSON의 일본어, 발음, 해석을 자동 편집/변환하지 않는다.
F. 영속적 id를 변경하는 데이터 마이그레이션을 함부로 하지 않는다.
G. 반복 구간 loopStart/loopEnd는 가사 간 반복과 수동 A/B 반복이 공유한다.
H. 줄 클릭/학습 체크/줄 반복은 각각 독립된 버튼 동작이다.
```

## 5. 리팩터링 허용 범위

- `SongPractice.tsx`가 길어졌다면 `useAudioPlayer`, `useLyricSync`, `LyricRow`, `AudioDock`, `RepeatPanel`로 나누어도 된다.
- 분리할 때 중요한 것은 브라우저의 `audio` 인스턴스가 **하나**라는 점이다.
- 재생 중 `requestAnimationFrame` 타이머는 언마운트/일시정지 시 반드시 취소.
- 멈춘 상태에서 `audio.currentTime`을 변경해도 현재 가사 상태가 즉시 바뀌어야 한다.
- 버튼 disabled 상태는 UI뿐 아니라 동작 로직에서도 확인한다.
- CSS 테마 변수는 유지하고 필요할 때만 확장한다.

## 6. 검사 순서

### A. 데이터 안정성

1. `scripts/validate-songs.mjs` 실행.
2. 신규 곡 JSON을 추가해 홈에 보이는지 확인.
3. `audioSrc: ""` 곡에서 텍스트만 정상인지 확인.
4. 타임코드 전부 없음 / 전부 있음 두 모드 각각 확인.
5. TXT 변환 도구의 중복 덮어쓰기 방지 확인.

### B. 기능 무결성

1. HTMLAudioElement 재생/일시정지.
2. 탐색, 이전/다음 줄, ±5초, 속도, 음량.
3. A/B 순서 오류 처리.
4. 짧은 한 줄 반복 경계.
5. 암기 모드 공개/숨김/종료.
6. 학습 체크/즐겨찾기 새로고침 후 유지.

### C. UI/접근성

1. 1440px, 1024px, 768px, 390px 뷰포트 확인.
2. 현재 줄 대비와 한글 발음 글자 읽기 편의 확인.
3. 아이콘만 있는 버튼에 라벨 존재.
4. 키보드 포커스 표시/단축키 충돌 없음.
5. 가사 길이가 길어져도 가로 스크롤 발생하지 않음.

## 7. 도입 금지 안티패턴

- 가사 JSON을 DB에 저장하려고 Prisma/MongoDB/PostgreSQL 설치.
- 사용자가 요청하지 않은 자동 번역/루비/후리가나 생성.
- YouTube 플레이어 삽입이나 상용 음원 자동 수집.
- MP3를 기초 웹앱에 붙이려고 별도의 음원 서버 구축.
- 브라우저 localStorage에 MP3 전체 Blob/베이스64 저장.
- 모든 가사 줄을 한 개의 긴 문자열로 만든 다음 단순 split에 의존.
- UI에 테스트용 저작권 노래 가사·앨범아트 무단 복제.
- 사용자에게 유료 API 키나 계정을 요구.

## 9. 이번 예제의 검증 한계

기본 제공본은 JSON 검증과 TXT 변환 테스트를 수행했다. npm 패키지 레지스트리에 접속할 수 없는 작성 환경의 네트워크 제한으로 실제 Next.js 설치/빌드/스크린샷 통합 테스트는 수행되지 않았다. 개발 에이전트가 네트워크가 있는 PC에서 해당 테스트를 **첫 번째 작업으로 실행**해야 한다.
