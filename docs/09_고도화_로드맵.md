# 09. 향후 개선 아이디어 (현재 범위 밖)

> 이 문서는 **가능한 발전 방향**을 기록할 뿐, 현재 사이트에 추가 구현을 요구하지 않는다. 현재 웹사이트는 요청한 로컬 가사 연습 기능을 우선한다. 향후에도 로컬/수동 입력 중심 철학을 유지한다.

## 우선순위 P1 — 사용자 편의 개선

| 아이디어 | 기대효과 | 구현 시 유의점 |
| --- | --- | --- |
| 로컬 가사 JSON 편집 화면 | VS Code 없이 문장 수정 | 파일 쓰기 기능이 필요하면 별도 로컬 전용 API 설계; 인증·외부 공개 금지 |
| 타임코드 박자 맞추기 도구 | 노래 들으며 줄 시작/종료 버튼 지정 | 자동 음성 분석이 아닌 **사람이 눌러 시간을 기록**하는 기능 |
| 학습 기록 JSON 백업/복원 | 브라우저 데이터 삭제 대비 | 개인 JSON 다운로드/선택한 로컬 파일 가져오기(외부 서버 불필요) |
| 가사 크기 조절 | 사용자별 시력·취향 반영 | 폰트 크기 저장 시 모바일 넘침 검사 |
| 표시 설정 빠른 프리셋 | 발음만 보기/전체 보기 등 전환 | 최소 1개 항목 표시 정책 유지 |

## 우선순위 P2 — 학습 경험 개선

| 아이디어 | 설명 |
| --- | --- |
| 전체 후렴 반복 | 후렴 섹션의 시작/끝을 묶어 반복 |
| 연습 세션 타이머 | 한 번에 몇 분 연습했는지 로컬 기록 |
| 가사 암기 순서 무작위 | 학습 테스트용 줄 임의 제시 |
| 선호 속도 곡별 기억 | `localStorage`에 곡 ID별 속도/음량 저장 |
| 박자 표식 / 구간 마커 | 타임코드 작성의 편의성 증대 |
| 로컬 플레이리스트 | 파일 기반 목록/연속 재생 — 노래 순서만 관리 |

## 제외 유지 — 서비스화 방향

- 서버 계정/다중 사용자/결제/광고/클라우드 동기화.
- 자동 번역, 일본어 음역 생성, 대형 AI 모델 연동.
- 웹상의 상용 음원 자동 다운로드/가사 수집.

## 개선 판단 기준

1. 원래 목적(노래 암기)에 직접 도움이 되는가?
2. 로컬 파일/비개인정보 전송 원칙을 유지하는가?
3. 음악보다 설정과 관리가 복잡해지지 않는가?
4. 일본어를 못 읽는 한국어 사용자의 가독성을 해치지 않는가?
5. DB 없는 운영으로 감당 가능한가?

**결론:** 기능 추가보다 **한 줄을 더 편하게 따라 부르는 경험**을 먼저 다듬는다.
