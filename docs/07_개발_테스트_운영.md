# 07. 개발 / 검수 / 운영 가이드

## 1. 지원 환경

- 권장 운영체제: Windows 10/11, macOS, Linux 중 Node.js 실행 가능 환경.
- Node.js: **20.9 이상** (`node -v`로 확인).
- npm: 설치된 Node.js에서 제공하는 버전.
- 브라우저: 최신 Chromium 계열(Chrome, Edge) 권장. 다른 브라우저는 미디어 API 차이 테스트 권장.
- 최초 `npm install`: 네트워크 연결이 필요할 수 있음.
- 로컬 이용 중: 외부 번역/API 서버 불필요.
- 서버 저장소: `content/songs/` JSON 파일, `public/audio/` MP3.

## 2. Windows 실행 절차

1. Node.js를 설치한다.
2. `가사봄_로컬웹_전체프로젝트.zip`을 예를 들어 `C:\Projects\gasabom_local\`에 압축 해제한다.
3. VS Code 또는 Windows Terminal에서 해당 폴더를 연다.
4. 다음을 차례로 실행한다.

```powershell
node -v
npm install
npm run validate:data
npm run dev
```

5. `http://127.0.0.1:3000`에 접속한다.
6. 이용을 마친 후 터미널에서 `Ctrl + C`로 서버를 중단한다.

기본 개발 서버는 `127.0.0.1` 주소에만 바인딩된다. 인터넷에 배포하거나 네트워크 전체에 공개하는 것이 목적이 아니다.

## 3. 개발 품질 검사

```bash
npm run validate:data    # JSON 스키마/MP3 경로/시간 정보 점검
npm run typecheck        # 타입스크립트 검사
npm run build            # Next.js 프로덕션 빌드
```

빌드가 성공하면 다음과 같이 로컬 프로덕션 실행도 가능하다.

```bash
npm run start
```

**운영 권장:** 새 JSON/MP3를 자주 바꾸는 개인 연습 환경에서는 `npm run dev`가 편리하다. Next.js 프로덕션 빌드에서는 `public/`의 신규 파일 처리나 빌드 캐시 특성이 다를 수 있으므로 정적 자원을 추가한 뒤 재빌드하는 것이 안전하다.

## 4. 데이터 QA 체크리스트

- [ ] `npm run validate:data` 결과 오류 0건.
- [ ] 추가한 노래의 `id`와 파일명이 일치한다.
- [ ] 각 노래의 가사 `line.id`가 중복되지 않는다.
- [ ] `ja`, `koPronunciation`, `koTranslation`이 정확히 기재되었다.
- [ ] `/audio/...mp3`가 실제 `public/audio/...mp3`와 같다.
- [ ] 타임코드가 있는 곡의 모든 줄이 시작·종료 숫자를 가진다.
- [ ] 가사/MP3가 **동일 음원 버전**에 맞춰 작성되었다.
- [ ] JSON 템플릿 `_TEMPLATE.json`이 화면에 보이지 않는다.

## 6. 로컬 데이터 백업

실제로 백업할 것:

```text
content/songs/      ← 직접 작성한 가사·발음·번역
public/audio/       ← MP3 원본
public/covers/      ← 개인 커버를 사용한다면
```

**중요:** 학습 체크/즐겨찾기는 별도 JSON 파일이 아니라 **브라우저 localStorage**에 있으므로 위 파일만 복사해서는 학습 기록이 백업되지 않는다. 현재 버전에는 학습 기록 파일 내보내기 기능이 없다. 브라우저의 사이트 데이터를 지우지 않도록 유의하며, 필요하면 추후 개선 항목의 JSON 내보내기 기능을 추가할 수 있다.

## 7. 주요 문제 해결

### 웹사이트가 열리지 않음

- `npm run dev`를 실행한 터미널이 계속 켜져 있는지 확인.
- `127.0.0.1:3000` 주소인지 확인.
- 포트 사용 중이면 `npm run dev -- --port 3001`로 변경 후 `127.0.0.1:3001` 접속.
- 두 포트는 서로 다른 localStorage 출처로 간주되므로 학습 체크·즐겨찾기가 다르게 보일 수 있음.

### 가사가 안 보임

- `npm run validate:data` 실행.
- `_TEMPLATE.json`을 그대로 둔 채 수정한 것은 아닌지 확인.
- `song.id`와 `.json` 파일명이 같은지 확인.
- 문법 오류: trailing comma(맨 끝 쉼표), 큰따옴표 누락, 잘못된 역슬래시 등을 검사.

### 노래가 안 나옴

- `public/audio/song.mp3`가 실제 존재하는지 확인.
- JSON의 `audioSrc`는 반드시 `/audio/song.mp3` 사용.
- 파일명 대소문자/확장자 확인.
- 일부 코덱을 `.mp3`로 이름만 바꾼 경우 정상적인 MP3로 변환 필요.
- 브라우저 자동재생은 정책상 제한되므로 재생 버튼을 사용.

### 글자는 보이지만 현재 줄이 안 바뀜

- 모든 가사 줄에 start/end가 있는지 확인.
- 타임코드 단위는 **초**, 분:초 문자열이 아님.
- 음원 metadata가 로드되었는지 확인.
- 반주/인스트 편집본과 타임코드가 서로 맞는지 검토.

## 8. 저작권 및 안전 운영

이 프로젝트는 사용자가 개인적으로 노래 연습할 수 있도록 로컬에서 파일을 표시한다. **상업적 유통 여부와 무관하게 음원·가사에는 저작권이 있을 수 있다.** 본인에게 허용된 사용 범위를 지키며 MP3나 전체 가사를 제3자에게 배포하지 않는다.

앱은 업로드 API가 없고 기본 개발 서버를 `127.0.0.1`에 바인딩하지만, 개인 PC의 파일 접근권한/백신/계정 보안까지 대신 관리해 주지는 않는다. 공용 네트워크 공개를 위해 기본 설정을 변경할 이유가 없다.

## 9. 제공본의 검증 범위

- 예제 JSON 파일 3개에 대해 구조 검증 완료.
- TXT→JSON 변환 성공 및 출력 JSON 재검증 완료.
- 자체 제작 예제 MP3 2개를 미디어 분석 도구로 확인.
- **제공 환경의 npm registry DNS 접속 실패로 의존성 설치/Next.js `typecheck`, `build` 및 브라우저 통합 테스트는 수행하지 못함.** 설치 가능한 사용자 PC에서 3단 검증(`npm install`, `npm run typecheck`, `npm run build`)과 위 수동 테스트를 진행해야 함.
